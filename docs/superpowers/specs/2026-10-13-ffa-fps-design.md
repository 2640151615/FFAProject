# 竞技向 FPS（纯第一人称 / 移动端）设计文档

- 日期：2026-10-13
- 工程：`FFAProject`（Rojo 7.7.1，`rojo serve` 已可运行）
- 状态：待评审

---

## 1. 意图与为什么

在 Roblox 上做一个**竞技向、纯第一人称**的枪战游戏，从零开始。

`TextProject` 是一份实验性质的武器验证工程——它的价值在于验证了若干技术路径（服务器权威命中、视图模型挂载、后坐力曲线），但它是边试边写长出来的，结构服务于验证而非产品。`FFAProject` 是一个干净的正式起点，**不复用其代码**，只借鉴其已踩过的坑。

**成功的样子**：两个 PC 玩家、或一个 PC 玩家对一个手机玩家，能打出一局双方都认账的对枪——谁的枪法好谁赢，而不是谁的网络好或谁会作弊。

### 明确的目标 / 非目标 / 反目标

**目标**
- 纯第一人称：任何时候都不出现自己角色的第三人称视图
- 竞技向：胜负主要由精准度和反应决定，弹药随机性降到最低
- 支持 PC、手机、平板
- 服务器权威：所有伤害与命中结果由服务器裁定

**非目标**（本设计不做，但结构上不堵死）
- 团队赛、占点、夺旗等非 FFA 模式
- 段位/匹配系统、排行榜持久化
- 皮肤、开箱、任何变现
- 载具、技能、装备系统

**反目标**（做出来就算失败）
- 客户端上报伤害数字（作弊器一改就崩）
- 为了兼容移动端把 PC 手感做成"自动瞄准大战"
- 移动端 UI 做成屏幕上一堆按钮糊满
- 为了先出内容而跳过手感打磨——竞技向游戏手感不对，内容再多也没人玩

## 2. 约束

| 约束 | 影响 |
|---|---|
| Roblox 引擎 | 网络模型、物理、渲染都由引擎决定，不可替换 |
| Rojo 7.7.1 + 文件系统 | 磁盘是唯一真相源；Studio 只是运行时 |
| 视图模型是**资产** | 枪+手臂的 3D 模型必须在 place 内，不能用 asset id 运行时加载 |
| 从零开始 | 无既有代码可继承，但 `TextProject` 可作为技术参考读物 |
| 竞技向 + 移动端同存 | 二者目标冲突，已用「同服混排 + 弱辅助」化解，见 §5 |

## 4. 我的判断（builder 可推翻，但请先说明理由）

**架构层**
- **服务器权威 + 客户端预测表现层**：客户端只发"开火意图"，服务器做 raycast 与伤害。
- **服务器位置回溯（延迟补偿）属于核心，不是后期优化**：Fire 请求带时间戳，服务器要把其他玩家回溯到开火那一刻的位置再判定。没有它，高延迟与移动端玩家打不中人，直接违反成功标准。
- **限速**：令牌桶限制 Fire 频率（射速校验之外的第二道闸）。

**内容层**
- **模式：多人混战（FFA）**（你定）：所有玩家互为敌手，无队伍。先到 N 杀结束（`Config.ScoreLimit`）。
- **单服人数 12**（我的判断，可调）：够热闹，又不至于让出生点变成绞肉机、网络压力失控。
- **加入即参战，无大厅**；到 ScoreLimit → 结算 → 自动重开。
- **武器数据驱动**：一张 `Weapons.luau` 驱动全部逻辑；加枪不改逻辑代码。

**角色与判定**
- **R6 骨架**（你定）：射线打 6 个部件——`Head` 吃爆头倍率，`Torso` 与四肢走倍率表。相比 R15，部件更少更方正、命中判定更可预测（竞技向常偏好这一口）；代价是动画表现力弱，且没有上/下臂之分，第一人称手臂必须完全依赖视图模型。
- **使用 Roblox 默认 Humanoid 移动控制器**：移动端支持白送；保留自定义接口，手感不对再换。
- **出生保护**：短暂无敌，**开火或移动即失效**。防堵出生点，又避免被当免死金牌滥用。
- **死亡后无击杀回放**：纯第一人称下不播自己尸体——死亡画面 + 重生倒计时。

**表现层**
- **脚步空间音效是设计需求**，不是纯资产选择：竞技向里脚步是战术信息。
- **目录结构**：`src/{server,client,shared}`，与已建好的 Rojo 工程一致。

## 5. 移动端与辅助瞄准（已定）

**同服混排**：PC 与触屏玩家进同一批服务器，不做输入池隔离。

**触屏给弱辅助**：仅在开火时提供极轻微的目标吸附 / 转向减速，**不做自动跟枪**；腰射与开镜区别对待（开镜时辅助更弱或归零）。目的是在不撞反目标的前提下，把"输入设备差异"造成的劣势压到可接受范围。

这一条同时定死两件事：

- 需要一个**独立的辅助瞄准模块**，纯客户端表现，服务端不参与；且必须**可调、可关**，方便后续按数据调平衡。
- 竞技平衡的基准是 **PC 手感**。辅助瞄准是补偿手段，不能反过来牵引数值设计。

**这是本设计里最容易做错的地方**：辅助一旦写成"自动跟枪"，游戏性质就变了。它的正确形态是"手指差一点点也能打中"，不是"不用瞄也能打中"。

## 6. 架构

### 6.1 权威分工

```
客户端                          服务器
──────                          ──────
按下左键
  ├─ 本地立即表现              收到 Fire 请求（朝向 + 时间戳）
  │  枪声 / 后坐力 / 枪口火焰        ├─ 校验：限速？活着？武器合法？
  │  （手感，允许预测）             ├─ 射速校验
  └─ 发 Fire 请求 ───────────►     ├─ 校验：限速？活着？武器合法？射速？
                                   ├─ 将其他玩家回溯到时间戳那一刻的位置
                                   ├─ 在该快照上 raycast 命中判定
                                   ├─ 扣血 / 判定击杀
                                   └─ 广播结果 ───────► 命中反馈 / 击杀提示
```

**铁律**：客户端报的任何数字都不可信。服务器只接受"意图"，不接受"结果"。

### 6.2 目录结构

```
src/
├── shared/                      两端都读，不含敏感数据
│   ├── Config.luau              常量（重生延迟、限速、分数上限）
│   ├── Weapons.luau             武器定义表（伤害/射速/弹匣/后坐力）
│   └── Net.luau                 远程事件集中定义
├── server/
│   ├── Bootstrap.server.luau    启动装配
│   └── services/
│       ├── CombatService.luau   ★ 命中判定、位置回溯、伤害，最核心
│       ├── WeaponService.luau   开火/换弹/切枪状态机
│       ├── SpawnService.luau    出生点选取、重生、出生保护
│       └── ScoreService.luau    击杀计数与记分板
└── client/
    ├── FirstPerson.luau         锁第一人称、隐藏自身身体
    ├── ViewModel.luau           手臂+枪挂到 Camera
    ├── WeaponController.luau    消费输入语义、本地开火预测
    ├── Recoil.luau              后坐力曲线
    ├── AimAssist.luau           触屏弱辅助（可调、可关）★
    ├── HudController.luau       准星、血量、弹药、击杀提示
    └── Input.luau               PC 鼠标 / 触屏 / 动态摇杆 输入抽象层 ★
```

`Input.luau` 是移动端要求逼出来的：输入必须走一层抽象，`WeaponController` 只消费"开火/换弹/切枪"语义，不关心来源是鼠标还是触摸。移动端的**移动与视角**则交给 Roblox 内置的动态摇杆 `PlayerModule`，不自己造——这是"屏幕不糊满按钮"的前提。

**这一层必须在 M1 就建**，事后补会很痛。

### 6.3 武器定义（数据驱动）

每把枪是一条表项，例如：

```lua
Rifle = {
    kind = "ranged",          -- "ranged" 射线 | "melee" 近战
    damage = 24,
    headshotMultiplier = 1.8,
    fireRate = 600,           -- 发/分
    automatic = true,
    magazineSize = 30,
    reloadTime = 2.2,
    range = 300,
    recoilPitch = 0.5,        -- 每发踢入相机的角度
    recoilYaw = 0.22,
    firstShotSpread = 0,      -- 竞技向：首发必准
}
```

竞技向意味着 **首发零扩散**（`firstShotSpread = 0`），扩散只在连发时累积。这是竞技与休闲的分水岭。

## 7. 里程碑

每个里程碑都可独立验证，做完就能上手玩。

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| **M1 骨架** | 工程跑通、玩家能出生 | Studio 连上、能走动、`Input.luau` 抽象层就位 |
| **M2 第一枪** | 一把枪能打死人 | 射线命中、**位置回溯**、扣血、死亡、3s 重生 |
| **M3 手感** | 让它"像 FPS" | 视图模型、后坐力、音效、命中反馈、准星 |
| **M4 多武器** | 1/2/3 切枪 | 弹药、换弹、切枪动画 |
| **M5 游戏循环** | 一局完整的 FFA | 计分、先到 N 杀结束、记分板、结算 |
| **M6 打磨** | 能给别人玩 | 地图、出生点、移动端 UI、延迟优化 |

**手感（M3）是最耗时间也最决定成败的阶段。** M1–M3 做完之前不碰 M4 之后的内容。
